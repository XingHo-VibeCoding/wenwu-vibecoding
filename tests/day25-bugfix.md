## Bug ①（主任务）：搜索结果点了不进详情页

### 现象
同一条场景数据有两个入口，点击行为不一致：

| 入口 | 点击后地址栏 | 页面表现 |
|---|---|---|
| 搜索结果（任务条目） | `#/transfer/scene-2` | ❌ 停在「传输指南」、滚到对应卡片 |
| 场景卡片（传输指南页） | `#/scene/scene-1` | ✅ 进入场景详情页（5 步） |

### 复现步骤（用户实机执行）
1. 打开 `https://wenwu-331122-d6gyrwmum2a734671-1498877015.tcloudbaseapp.com/wenwu-vibecoding/`
2. 在「① 找任务 / 场景」搜索框输入「交作业」
3. 点击搜索结果条目 → 观察地址栏与页面
4. 对照组：切「传输指南」→ 点 S1 卡片 → 观察地址栏与页面

### 证据
- **图 1（改前）**：搜索结果点击后地址栏为 `…/#/transfer/scene-2`，页面停留在传输指南、滚到卡片。
- **图 2（改后）**：搜索结果点击后地址栏为 `…/#/scene/scene-2`，页面为 S2 详情页（5 步渲染正常，顶部徽标「云数据库数据 · 实时」）。

### 定位（代码级，非推断）
- **位置**：`web/src/views/SearchView.jsx:96`
  ```jsx
  <a href={"#/transfer/" + t.scene_id}>   // ← 旧
  ```
- **根因**：Day 24 把卡片链接从「滚到卡片」改为「进详情页」（`TransferView.jsx` → `#/scene/`）时，**漏改了搜索结果这一处**。全项目 `grep '#/(transfer|scene)/'` 结果**仅此 1 处**仍在用 `#/transfer/`，范围干净、无第二处。
- **性质**：Day 24 改动的**连带回归**（非新功能缺失）。不崩溃、不白屏，属「交互不一致」。
- **排除项**：路由解析正常（图 2 证明 `#/scene/` 可进详情页）；非缓存问题（同一次加载下两入口行为不同）；非接口问题（详情页数据正常）。

### 修复
```diff
- <a href={"#/transfer/" + t.scene_id}>
+ <a href={"#/scene/" + t.scene_id}>
```
