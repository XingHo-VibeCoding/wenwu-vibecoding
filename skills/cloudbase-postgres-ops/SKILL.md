# CloudBase PostgreSQL 操作基线

本项目（《电子设备使用指南》）第 3 周起的数据库都在 CloudBase PostgreSQL 上。这份基线是 Day 16 实际跑通后沉淀的，**照做即可，不要重新摸索**。

## 1. 控制台入口（实测路径，勿照抄官方文档）

用户的控制台是**新版**，左侧导航：

| 入口 | 用途 |
|---|---|
| 数据管理 → **SQL 编辑器** | 执行建表 / 种子 / 查询脚本（今天所有 SQL 都贴这里） |
| 数据管理 → **数据编辑器** | 浏览表数据（截图交付用：表名 + 数据行） |
| 数据库管理 → 表 / 索引 / Schema 可视化 | 确认表是否建成、有几列 |
| 配置 | 「重置密码」不要点（会断开所有连接）；外网 IPv4 不要开（云函数走内网）；SSL 强制保持关 |

⚠️ **官方文档里那套「先建账号 → 进 DMC 工具」的路径对本环境不适用**（那是旧版/通用版）。不要照着官方文档引导用户，会白折腾一轮。**引导前先要一张用户实际界面的截图**。

## 2. 两段式脚本约定（本项目定稿）

| 文件 | 职责 | 可重复执行的实现 |
|---|---|---|
| `db/schema.sql` | 建表（主键 / 外键 / 约束 / 索引 / 字段注释） | 开头 `DROP TABLE IF EXISTS ... CASCADE`，**反序删**（先子后父） |
| `db/seed.sql` | 灌数据 | 开头 `TRUNCATE TABLE t1, t2, ... RESTART IDENTITY CASCADE` |

- 执行顺序固定：**先 schema，再 seed**。
- 建表语句**单一来源**，不在 seed 里重写一份（否则改表要改两处）。
- 自增主键用 `integer GENERATED BY DEFAULT AS IDENTITY`（PG 10+ 标准，别用 `serial`）。
- 外键一律 `REFERENCES x(id) ON DELETE CASCADE`。
- **PG 不会给外键自动建索引**，常用外键手动补 `CREATE INDEX`。
- 枚举用 `CHECK (x IN (...))`，不为固定小集合建字典表。
- 需要表达"未实测"时用 **NULL + 一个 `measure_status` 状态列**：PG 的 `CHECK` 遇 NULL 视为通过，正好利用这一点。
- 字段注释（`COMMENT ON`）**放文件末尾**：万一控制台粘贴被截断，建表部分已经先跑完了。

## 3. ⚠️「破坏性操作」提示属预期

SQL 编辑器遇到 `DROP` / `TRUNCATE` 会弹「破坏性操作」确认框。

- **这是设计出来的，不是脚本写错**。确认继续即可。
- 判断其是否安全的唯一依据：**表里的数据能不能重灌**。本期数据全部来自 `seed.sql` → 安全。
- 一旦库里出现**不可重建的真实数据**（用户投稿等），`schema.sql`（含 DROP）**不得再整份执行**，必须先导出备份。
- 若控制台**直接拒绝**（不是确认弹窗），降级方案：执行去掉 DROP 段的"只建表"版本，删表改在「数据库管理 → 表」界面手动做。

## 4. 字段命名避坑（Day 16 实际撞过）

建表前必须检查列名是否与 SQL 关键字 / 类型名撞车：

| 危险名 | 问题 | 改成 |
|---|---|---|
| `desc` | SQL 保留字（`ORDER BY x DESC`），**建表直接语法报错** | `description` |
| `time` | PG 类型名 | `time_cost` |
| `text` | PG 类型名，`text text NOT NULL` 读写别扭 | `content` |
| `use` | 易与 SQL 命令混 | `purpose` |
| 与表名同名的列（如 `instruments.steps` vs 表 `steps`） | `SELECT steps FROM instruments` 看不懂 | `step_list` |

另外：字符串一律用 `text`，**不要 `varchar(n)`**（PG 里性能相同，text 免去改长度的迁移）。

## 5. 数据原则：宁缺不编

- 抽不到真实内容的字段**存 NULL**，不造示例值；另设状态列（如 `measure_status`）标明"待实测"。
- 从 HTML 抽取正文时，**剥离 `<b>` / `<code>` 等标签只留文字**，并在脚本头注释里**如实写明这是有损处理**。
- 内容里的 ASCII 单引号按 SQL 规则**双写**（`'It''s ok'`），否则脚本报错。
- 抽取前**先把来源读一遍并记录行号**，方便日后溯源。

## 6. 验证模板（写完必跑，别靠目测）

**行数核对**（一条 UNION 拿到全部表行数）：

```sql
SELECT 1 AS ord, 'scenes' AS table_name, count(*) AS row_count FROM scenes
UNION ALL SELECT 2, 'steps',       count(*) FROM steps
UNION ALL SELECT 3, 'resources',   count(*) FROM resources
UNION ALL SELECT 4, 'instruments', count(*) FROM instruments
UNION ALL SELECT 5, 'tasks',       count(*) FROM tasks
ORDER BY ord;
```

**关联验证**（确认外键真的工作）：

```sql
SELECT s.no, s.name, count(st.id) AS step_rows
FROM scenes s LEFT JOIN steps st ON st.scene_id = s.id
GROUP BY s.no, s.name ORDER BY s.no;
```

⚠️ **SQL 编辑器可能只显示最后一个结果集**。脚本里有多条 SELECT 时，要么分次执行，要么明确告诉用户"往上翻/单独重跑第一条"——否则会以为第一条没跑。

**写文件后的自检**：本地通常没有 PostgreSQL，语法无法真跑。可以用 python 正则统计脚本里的 `VALUES` 行数（如 `\('scene-\d', \d+,`）来核对条数，**用脚本数，别用眼睛数**，并把结果如实标注为"未经真实执行"。

## 7. 本项目环境坑（别再踩）

- **PowerShell 工具的 stdout 捕获失效**：命令输出必须写进临时文件，再用读文件工具看。
- **临时文件清理只用 `[System.IO.File]::Delete()`**，并用 Glob 复核；`Remove-Item` 的成败都不可信。
- **PowerShell 里 `if (...) {...} else {...} | Out-File` 会让整段不执行**，拆成独立语句。
- 命令里含 `%` 会被安全策略拦截。
- 环境变量 / 连接串 / 账号密码：**不进代码、不进 Git、不进聊天**；截图避开填密码的弹窗。
